# Errata Protocol

This document records the systematic verification protocol and audit log for correcting inaccurate, stale, or hallucinated data across the repository.

## Data Verification & Correction Protocol

To maintain data integrity across investment dossiers, valuation models, and trading plans, any detected error or discrepancy must undergo a formal correction lifecycle:

```
+-------------------------------------------------------------------------+
| Step 1: Detection & Discrepancy Flagging                                |
| Flag conflicting claim -> Cross-reference against Tier 1 SEC EDGAR     |
+-------------------------------------------------------------------------+
                                    |
                                    v
+-------------------------------------------------------------------------+
| Step 2: Triangulation & Primary Source Verification                     |
| Retrieve official filing or direct exchange proof -> Confirm ground truth|
+-------------------------------------------------------------------------+
                                    |
                                    v
+-------------------------------------------------------------------------+
| Step 3: In-Place File Correction & Provenance Update                     |
| Update target dossier/schema -> Append provenance citation & audit note |
+-------------------------------------------------------------------------+
                                    |
                                    v
+-------------------------------------------------------------------------+
| Step 4: Errata Registry Logging                                         |
| Append structured record below matching context/schemas/errata_schema.json|
+-------------------------------------------------------------------------+
```

## Error Taxonomy

1. **HALLUCINATION:** Plausible-sounding data point generated by an AI agent that has no basis in official filings or factual records.
2. **STALE_PARAMETRIC_MEMORY:** Outdated figure retained in model internal weights that has been superseded by recent events or quarterly filings.
3. **TRANSCRIPTION_ERROR:** Typographical or parsing mistake made during OCR, screenshot ingestion, or manual data entry.
4. **UPSTREAM_API_ANOMALY:** Flawed, unadjusted, or missing data provided by a secondary aggregator API.
5. **METHODOLOGY_CALCULATION_ERROR:** Mathematical or formula error in DCF modeling, Black-Scholes Greeks, or option limit calculations.
6. **CORPORATE_RESTATEMENT:** Company retroactively restates past financial filings with the SEC.

## Resolution Procedures for Target Dossiers

When an erratum is resolved:
1. The target file in `context/theses/` or `http/data/` is updated immediately with the correct figure.
2. A note is appended to the file's thesis log referencing the `Erratum ID` and primary source.
3. The errata registry above is updated with status `RESOLVED`.
