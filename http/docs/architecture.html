System Architecture

Specialized sub-agent pipeline, data boundary isolation, and deterministic context construction.

Why Agent Teams Outperform Monolithic Chatbots

Standard LLM chatbots struggle with personalized portfolio management due to session amnesia, guardrail hedging, narrow market scope, and lack of derivatives modeling. This system resolves these limitations by orchestrating specialized sub-agents backed by deterministic local memory stores.

Sub-Agent Roles & Pipeline

1. Portfolio Ingestion Agent

Input: Brokerage screenshot or CSV export in private/snapshots/.

Responsibility: Extracts share counts, options contracts, cash balances, SGOV shares, isolates distinct accounts, and tags covered call eligibility (>= 100 shares).

2. Equity Research Agent

Input: The Internet, US public markets (NYSE, NASDAQ, AMEX), SEC EDGAR filings, and screening tools.

Responsibility: Discovers compelling public companies, checks balance sheet solvency/runway, screens for experimental hypothesis of achieving >= 20% annualized ROI, and onboards single or batch equities into our coverage universe on demand.

3. Investment Thesis Agent

Input: Tracked universe of equities backed by Tier 1 SEC EDGAR filings (10-K/10-Q) and earnings releases.

Responsibility: Authors the researched assumptions behind 3-year forecasts, constructs Revenue & P/S narratives, and supplies the qualitative judgment required for BUY, HOLD, SELL, or AVOID ratings.

4. Memory Agent

Role: Generative cross-run reasoning and invalidation alerts.

Tools invoked: manage_memory.py, activity_ledger.py, errata_log.py.

Reads: context/theses/*.md, context/research/runs/, context/research/errata/, context/research/errata_protocol.md.

Responsibility: Tracks cross-run continuity, evaluates multi-quarter catalyst outcomes, audits invalidation criteria, and flags broken theses for decisive liquidation (including BUY TO CLOSE mandates on open derivatives).

5. Pricing Agent

Input: Thesis price targets, technical support/resistance levels, moving averages, and volatility data.

Responsibility: Predicts price trends to calculate technical limit orders, models Black-Scholes pricing for Cash-Secured Puts and Covered Calls, verifies net-credit rolls, and computes Buy to Close (BTC) limit prices on losing propositions.

6. Lead Portfolio Manager

Input: Sub-agent reports and policy constraints.

Responsibility: Synthesizes executive decisions into a concise plain-text Weekly Trading Plan (private/plans/YYYY-MM-DD-plan.txt) with single-session Monday execution (issuing BUY TO CLOSE orders on losing propositions to eliminate assignment risk or unlock shares for sale).

The Research Store Is the System Boundary

The canonical public record for a company is context/data/equities/<TICKER>.json. Observed facts, source provenance, agent-authored qualitative judgments, and forward-looking parameters live there under the schema. Thesis Markdown, web JSON, valuation outputs, and return outputs are derived artifacts.

Work type Who performs it Rule
Source research and narrative judgment Specialized agent Write sourced facts and bespoke reasoning into the research store.
Forecast and valuation parameters Specialized agent Author explicit assumptions; do not hide them in rendered prose.
Math, bulk checks, and schema validation Deterministic script Compute from stored inputs and fail when a required input is missing.
Thesis and web rendering Deterministic script Render only stored prose and computed values; never invent a fallback.
Portfolio orders and rationale Lead Portfolio Manager Agent Author each decision in a private order set before validation and rendering.
Onboarding is not research

scripts/onboard_company.py can register a symbol and ingest available public facts, but a newly onboarded equity remains AWAITING_RESEARCH. It receives no valuation, target ROI, or rating until agents author the required research and deterministic engines validate the result.

Data Isolation & Privacy Model

The system enforces strict data privacy through isolated directory tiers:

  • Private User Tier (private/): All user snapshots, exact account values, and personalized execution plans are stored locally and git-ignored.
  • Public Intelligence Tier (context/theses/ & http/): Fundamental company research, catalyst timelines, and valuation models contain zero private user data and are committed to version control.
  • Deterministic Engine (scripts/): Python scripts execute mathematical models and API connectors locally.
Audit Artifacts: Three-Layer Model

Field provenance lives in each equity research record. Agent run logs (context/research/runs/{run_id}.json) record bounded generative sessions. Errata registry (context/research/errata/{erratum_id}.json) records verified corrections. Generative agent roles invoke deterministic scripts to read and write these layers; scripts are never agents.

Deterministic Context Construction

Agents read targeted structured records, schemas, prompts, and derived dossiers instead of relying on conversational memory alone. This makes assumptions inspectable and calculations reproducible, while source verification and human review remain necessary.
