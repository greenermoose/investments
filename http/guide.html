How to Use This Repository

Use the agent team to turn a current brokerage snapshot and verified public research into one account-by-account trading plan for the coming week.

You remain the decision-maker and order executor

The repository does not connect to a broker, place trades, or guarantee returns. It produces research and a validated plan for educational use. Equities and options can lose all value. Review every order before entering it.

The Mental Model: You Ask, Agents Decide, Scripts Verify

This is an AI-assisted investment workspace, not a traditional point-and-click portfolio application. The human supplies current private account facts and the desired outcome. Specialized agents research, reason, and author recommendations. Deterministic scripts perform parsing, calculations, collateral checks, schema validation, and rendering.

Human

Supply and execute

  • Export fresh account snapshots.
  • Request a weekly plan or research job.
  • Check the final plan against the brokerage account.
  • Enter the specified limit orders.
Agent team

Research and decide

  • Keep every account separate.
  • Assess theses, catalysts, invalidations, and prices.
  • Choose each trade and write its rationale.
  • Produce one definitive execution plan.
Deterministic tools

Calculate and reject errors

  • Parse supported brokerage exports.
  • Calculate prices, Greeks, AROC, and cash impact.
  • Enforce cash and share collateral.
  • Refuse to render an invalid order set.
The trading plan is the action document

The Equity Explorer shows public research and ratings. It does not know your account balances or tell you what to trade. Personalized actions appear only in the dated plain-text plan under private/plans/.

First-Time Setup

1

Open the repository in an AI coding workspace

The agent needs access to this repository so it can read the mandate, skills, research store, prompts, schemas, and scripts. Start the conversation from the repository root.

2

Browse the portal

Ask the agent to start and open the local Investments Portal, or serve the http/ directory yourself and open http://localhost:8080/.

python -m http.server -d http 8080
3

Understand the mandate before using a plan

Read the Investment Mandate. In particular: US-listed common stocks, a long-term >= 20% annualized hurdle, limit orders, no naked options, no speculative long options, and one weekly execution session.

4

Review a synthetic example

Compare examples/sample_portfolio.csv, examples/sample_orders.json, and examples/sample_trading_plan.txt. These show the expected input, the agent-authored decisions, and the final human-facing output without exposing real account data.

The Core Weekly Routine

Most human use of the repository should follow this loop. The system is designed for a weekend review, one order-entry session on Monday, and automatic option settlement on Friday.

Friday close or weekend
Export current snapshots

Capture balances, every position, and all open options after the prior week has settled.

Weekend
Request and review the plan

The agents deliberate, author orders, validate collateral and arithmetic, and render the plan.

Monday 9:30 AM ET
Enter all limit orders

Execute Portfolio 1 completely, then Portfolio 2, following any entry-time branch exactly.

Friday 4:00 PM ET
Let expirations settle

No mid-week babysitting is expected. Start again with a fresh snapshot after settlement.

Step 1: Export complete brokerage snapshots

CSV exports can be parsed by a deterministic script. A clear screenshot can be interpreted by a generative AI agent. Save inputs under private/snapshots/ with the date and account name in the filename.

Each account snapshot must show

  • Account name or an unambiguous masked label.
  • Total account value and settled cash.
  • Symbol, quantity, market value, and cost basis for every holding.
  • SGOV quantity and value, when present.
  • Every open option, including quantity, expiration, strike, put or call, and current mark.

For multiple accounts

Use a distinct file or clearly separated account section for each account. Never pre-combine balances or holdings. The system validates collateral inside each account and cannot borrow cash or shares from another one.

Step 2: Ask for the dated weekly plan

A short outcome-based request suffices. The repository instructions and skills contain the operating protocol.

Suggested request

Generate the weekly trading plan for Monday [DATE] using every current snapshot in private/snapshots/. Keep all accounts separate, refresh or verify the public intelligence needed for the decision, resolve material research gaps, author and validate the complete order set, and save the final plain-text plan to private/plans/[DATE]-plan.txt. Return the definitive plan and clearly report any validation failure.

Step 3: Let validation finish

The Lead Portfolio Manager must decide every order and write an order set first. The renderer then checks account isolation, available cash, existing option encumbrances, covered-share blocks, limit prices, tracked symbols, cash impact, and AROC. If a check fails, no plan should be produced until the underlying order set or snapshot is corrected.

Step 4: Perform the human preflight

Open the dated file in private/plans/ and compare it with the brokerage screen. Do not treat a successfully rendered file as a substitute for this review.

  • The plan date and snapshot date are current.
  • Every account appears once, with the correct total value, cash, SGOV, holdings, and open options.
  • Every order has one action, symbol, quantity, order type, limit price, cash impact, and rationale.
  • Short puts are fully secured inside that account; short calls use only uncommitted 100-share blocks.
  • No order is a speculative option purchase, naked option sale, or market order.
  • Any branch depends only on the price visible when orders are entered, not on later monitoring.
  • The Friday expiration section matches every option expiring that week.
Correct the source, then regenerate

If a balance, holding, option, or cost basis is wrong, replace or correct the snapshot and ask the agent to regenerate the order set and plan. Do not hand-edit a quantity or price in the final plan because that bypasses collateral and arithmetic validation.

Step 5: Enter orders once, account by account

On Monday at 9:30 AM ET, or as soon as you can access the accounts, enter all orders for Portfolio 1 before moving to Portfolio 2. Use the stated limit prices. When the plan contains an execution-time branch, observe the current price once and enter only the matching branch. Let stated Friday expirations and assignments settle automatically, then provide a fresh snapshot the following weekend.

How to Read the Trading Plan

Account Snapshot

The facts used to size orders: total value, settled cash, SGOV, dry powder, and position count. Stop if these do not match the broker.

Action

The exact broker-side instruction, such as BUY, SELL, SELL TO OPEN, or BUY TO CLOSE. Do not substitute a different action.

Limit Price

The worst acceptable execution price. An unfilled order is preferable to silently replacing it with a market order.

Cash Impact and Collateral

The expected debit or credit and the cash or shares reserved for a short option inside that account.

Execution Contingency

A deterministic branch selected from the price visible during the single order-entry session. It is not a mid-week watch instruction.

Friday Expectation

The expected expiration, assignment, call-away, or collateral release for contracts expiring that week.

A plan with no trades can be correct

The system should not manufacture activity. When no order clears the research, valuation, pricing, and risk checks, the definitive recommendation can be to place no orders for that account.

Using the Equity Explorer

The Equity Explorer is the human view of public company intelligence. Use it to understand and challenge the research behind a plan, compare tracked companies, and locate source records. It contains no private portfolio quantities.

Grid Cards

Scan ratings and the locked 2 by 2 metrics: annualized Target ROI, diluted shares outstanding, TTM revenue, and enterprise value.

Dossiers

Compare the longer thesis summaries, valuation ranges, catalysts, moat, and invalidation logic across companies.

Data Table

Sort dense fields such as rating, benchmark entry, exit target, target ROI, sector, and 52-week range.

Open a company for the full record

Select a company from any view. The drawer separates the investment thesis, quarterly revenue path, analyst coverage, technical analysis, SEC filings, and company-specific strategy. Source links and filing dates help distinguish observed facts from model-authored forecasts.

Ratings are public research classifications

A BUY rating means the public thesis currently clears the system's return hurdle. It is not automatically a buy order for your account. Position size, existing exposure, available collateral, taxes, open options, and execution price are resolved only in the weekly plan.

Label How to use it
Target ROI Annualized modeled return, not total return and not a guarantee.
Benchmark Entry Price A public valuation reference. Your actual order limit is set from current fundamentals and technical conditions in the weekly plan.
Price Target Range Bear, base, and bull valuation scenarios for a stated horizon, not a promised future price.
Conviction Strength of the current thesis after research; it does not override portfolio-level risk checks.
Invalidation Criteria Specific evidence that would break the thesis and can require a SELL or defensive BUY TO CLOSE.

Other Useful Jobs to Give the Agent

Use outcome-based requests. The agent should select the relevant repository skill and deterministic tools, keep an activity record for public research work, and report what changed.

Explain or challenge a recommendation

Explain the [TICKER] order in the latest plan. Trace the recommendation to the public thesis, current valuation, technical limit, catalysts, invalidation criteria, and portfolio constraint that determined its size.

Add one or more companies to coverage

Research and onboard [TICKERS] into the tracked universe. Apply Stage 1 triage and solvency checks, use authoritative filings, complete the research store, render the public theses, and run quality control.

Find new candidates

Screen US exchanges for companies with a credible path to at least 20% annualized ROI. Apply the repository's triage gates and return one decisive ranked onboarding set.

Refresh stale public intelligence

Refresh [TICKER or UNIVERSE] from the authoritative sources required by the repository, identify research gaps, reconcile discrepancies, rerender affected public artifacts, and run quality control.

Correct a suspected error

Verify this claim against Tier 1 evidence: [CLAIM]. If it is wrong or stale, update the research store, rerender derived files, and record the correction in the errata registry.

Replace a stale plan

I did not execute the dated plan. Treat it as stale, use the newest account snapshots and market data, and generate a newly dated, fully validated plan. Do not carry old limits forward without recomputing them.

Keep Private and Public Data Separate

The repository has a strict one-way privacy boundary. Public intelligence may inform a private plan. Private account facts must never flow back into public research, the web portal, source code, run logs, or errata records.

Public intelligence
context/ http/ scripts/

Company research, market data, methods, and deterministic tools.

May inform one way only
Private execution
private/snapshots/ private/plans/

Account values, quantities, cost bases, open contracts, and personalized orders.

  • Keep real exports and screenshots only under private/.
  • Mask account numbers when the exact identifier is unnecessary.
  • Before sharing or committing changes, check that no private file or copied account value appears in a public directory.
  • Public thesis updates must describe companies objectively, without mentioning that you own them.

When Something Goes Wrong

The snapshot cannot be parsed

Export CSV when possible. Confirm the file contains a symbol column and recognizable quantity, price, market value, and asset-type fields. For screenshots, ask the agent to transcribe each account and reconcile its totals before authoring orders.

The account total does not reconcile

Stop plan generation. Check for omitted cash, money-market rows, unsettled transactions, open options, duplicated totals, or a stale export. Replace the snapshot and rerun ingestion.

A company is missing research

An unrated or AWAITING_RESEARCH company cannot carry a fabricated valuation or recommendation. Ask the agent to complete its research fields and validation before using it in a plan.

The order renderer rejects the plan

This is a safety result, not a formatting inconvenience. Correct the order set or snapshot that caused the collateral, share coverage, arithmetic, universe, or schema failure. Never bypass the failed check by manually writing a plan.

Market conditions changed before execution

If the plan contains a matching entry-time branch, use it. Otherwise treat the plan as stale and request a newly priced and validated plan. Never convert the old limit to a market order.

You discovered a bad public claim

Ask the agent to verify it against Tier 1 evidence and follow the errata workflow. The correction belongs in the research store and errata registry; private account information does not.
